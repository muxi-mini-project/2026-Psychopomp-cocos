# Psychopomp 项目开发规划

## 项目概述

Psychopomp 是基于 Cocos Creator 3.x 开发的解谜/冒险游戏，采用 Manager 单例模式架构。

---

## 一、已完成的核心系统

### 1.1 Manager 架构

| Manager | 职责 | 状态 |
|---------|------|------|
| GameManager | 游戏状态机、流程控制 | ✅ |
| DataManager | 存档、flag、物品管理 | ✅ |
| DialogManager | 对话播放控制 | ✅ |
| InventoryManager | 物品栏状态管理 | ✅ |
| InteractableManager | 交互点逻辑处理 | ✅ |
| SceneViewManager | 场景加载、预加载（Map） | ✅ |
| UIManager | UI 层级控制 | ✅ |
| ResourceManager | 资源配置加载 | ✅ |

### 1.2 交互点系统

- 支持 `setFlags`、`pickItem`、`switchScene`、`data.dialogueId`
- 发出 `INTERACTABLE_TRIGGERED` 事件

### 1.3 场景预加载系统

- 使用 Map 存储多个预加载场景
- 支持 `preloadScene`、`switchToScene`
- `scenes.json` 配置 `preloadNext` 邻接场景

### 1.4 物品与 Flag 系统

- `ADD_ITEM_REQUEST` 事件 → 拾取物品
- `SET_FLAG_REQUEST` 事件 → 设置 flag
- `FLAG_CHANGED` 事件 → flag 变化通知

### 1.5 UI 层级结构

```
Canvas
├── Managers (常驻)
├── sceneContainer (游戏场景)
└── UI
    ├── fullscreenLayer
    │   ├── mainMenu
    │   ├── gameOverScreen
    │   ├── videoPlayer
    │   └── IntroCutscene（待完成）
    └── gameLayer

        ├── menuPanel

```

## 八、GameManager 重构任务（架构级）

### 核心问题：初始化与进入游戏的职责混淆

**当前错误设计**：
```
游戏启动 → initializeGame() → 自动检查存档 → 自动进入 _startNewGame() 或 _resumeGame()
```

**问题**：
- `initializeGame()` 在游戏启动时被动的执行，但它内部调用了 `loadGame()` 检查存档
- 根据存档有无，自动走 ` _startNewGame()` 或 `_resumeGame()`
- 玩家根本没机会在主菜单做选择

**正确设计**：
```
游戏启动
    ↓
initializeGame()
    ├── 加载资源配置
    ├── DataManager 做基础初始化（无存档数据）
    └── 显示主菜单（SHOW_MAIN_MENU）
    ↓
等待玩家操作

玩家点击"新游戏"          玩家点击"继续游戏"
    ↓                        ↓
START_NEW_GAME ────────── LOAD_GAME
    ↓                        ↓
startNewGame()           loadGame()
（仅初始化数据，不保存）     ↓
    ↓                   进入游戏
播放开场动画/演出
    ↓
演出结束 → 存档 → 进入游戏
```

**三个操作的职责划分**：

| 操作 | 触发者 | 职责 |
|------|--------|------|
| `initializeGame()` | 系统（游戏启动时被动调用） | 基础初始化 + 显示主菜单 |
| `START_NEW_GAME` | 玩家（点击"新游戏"按钮） | 初始化新游戏数据 + 播放开场 |
| `LOAD_GAME` | 玩家（点击"继续游戏"按钮） | 加载存档 + 进入游戏 |

---

### 重构3：_onLoadGame() 完整实现（含开场状态检查）

**当前代码** (line 126-130)：
```typescript
private _onLoadGame(data: { slotId: string }): void {
    if (data?.slotId && DataManager.instance.loadGame(data.slotId)) {
        SceneViewManager.instance.initializeFromSave();
    }
}
```

**问题**：
- 未隐藏主菜单
- 未激活 gameLayer 和物品栏
- **未检查开场演出是否完成**

**重构后**：
```typescript
private _onLoadGame(data: { slotId: string }): void {
    if (data?.slotId && DataManager.instance.loadGame(data.slotId)) {
        director.emit("HIDE_MAIN_MENU");

        // 检查开场演出是否完成
        if (!DataManager.instance.getIntroPlayed()) {
            // 开场未完成：从头开始播放（视频 → 对话 → 设置flag → 进入游戏）
            director.emit("INTRO_START");
        } else {
            // 开场已完成：直接进入游戏
            SceneViewManager.instance.initializeFromSave();
            director.emit("SHOW_GAME_UI");
            director.emit("SHOW_INVENTORY_PANEL");
        }
    }
}
```

**设计说明**：
- `INTRO_PLAYED` flag 只在**对话演出完成**时才设置
- 视频播放完成不需要独立 flag，流程自动衔接到对话
- 读取存档后：若 flag 为 false，从视频重新开始；若为 true，直接进入游戏

**完整流程图**：
```
【新游戏流程】
START_NEW_GAME
    ↓
startNewGame()（数据初始化，无flag）
    ↓
播放视频 → INTRO_COMPLETE
    ↓
showIntroCutscene()（对话演出）
    ↓
对话结束 → setIntroPlayed(true) → 保存存档
    ↓
_enterGame()

【继续游戏流程】
LOAD_GAME
    ↓
loadGame()（加载存档数据）
    ↓
检查 INTRO_PLAYED flag
    ↓
    ├─ true → 直接进入游戏
    │
    └─ false → 播放视频 → 对话 → set flag → 进入游戏
```

### 修复1：移除 startNewGame() 中的立即保存

**问题**：`startNewGame()` (line 220-221) 在新游戏初始化后**立即**保存到 `auto_save`

```typescript
public startNewGame(): void {
    this._saveData = {
        saveId: "new_game",
        saveTime: Date.now(),
        gameVersion: GAME_VERSION,
        currentScene: "scene_intro",  // 硬编码场景ID
        storyFlags: {},
        inventory: [],
        visitedScenes: []
    };

    console.log("[DataManager] 新游戏已初始化");
    this.saveGame(AUTO_SAVE_SLOT, true);  // ← 问题所在：立即保存
}
```

**问题流程**：
```
1. 用户点击"新游戏" → director.emit("START_NEW_GAME")
2. GameManager._onStartNewGame() → DataManager.startNewGame()
3. startNewGame() 执行 saveGame(AUTO_SAVE_SLOT, true) → 立即写入 auto_save
4. 下次启动游戏 → initializeGame() → loadGame("auto_save") 返回 true
5. 进入 _resumeGame() → 因 introPlayed 已重置，直接播放开场
6. 结果：用户永远看不到主菜单
```

**设计要求**：
- 用户点击"新游戏" → 播放开场动画/演出 → 演出结束后才保存 `auto_save`
- 这样下次启动才有 `auto_save`，在此之前启动应显示主菜单

**修复**：
```typescript
public startNewGame(): void {
    this._saveData = {
        saveId: "new_game",
        saveTime: Date.now(),
        gameVersion: GAME_VERSION,
        currentScene: "",  // 开场演出阶段无场景
        storyFlags: {},
        inventory: [],
        visitedScenes: []
    };

    console.log("[DataManager] 新游戏已初始化");
    // 注意：此处不再调用 saveGame()
    // 存档将在开场演出完成后的 _enterGame() 或 _onIntroCutsceneComplete() 中进行
}
```

**关联修改**：
- `GameManager._enterGame()` 需要负责保存 `auto_save`
- `GameManager._onIntroCutsceneComplete()` 已有的保存逻辑保持不变

### 修复2：修正 currentScene 初始值

**问题**：`startNewGame()` 中 `currentScene: "scene_intro"` 硬编码

**分析**：
- 开场视频由 UIManager 通过 `playVideo()` 独立控制
- 对话演出由 UIManager 通过 `showIntroCutscene()` 控制
- 两者都不走 SceneViewManager 的场景加载
- 所以 `currentScene` 不应有 `scene_intro` 这样的值

**修复**：将 `currentScene` 改为空字符串 `""`

**后续场景切换**：
- 演出结束后 `_enterGame()` → `SceneViewManager.initializeFromSave()`
- 此时 DataManager 的 `currentScene` 应已被场景切换逻辑更新为正确的起始场景（如 `scene_bedroom`）

**问题**：line 308-310 定义了私有常量但未被使用

- `getIntroPlayed()` / `setIntroPlayed()` 实际上是通过字面量字符串 `"INTRO_PLAYED"` 访问 flag
- 这些私有常量是死代码，未被任何方法引用

**修复**：直接删除这两个私有常量（不影响功能）

---

### 修复4：明确 flag 设置时机（视频flag无需独立存在）

**设计决策**：
- 视频播放完成**不需要独立 flag**
- 视频播放完成后自动衔接到对话演出
- 只有**对话演出完成**后才设置 `INTRO_PLAYED` flag

**流程**：
```
播放视频 → 视频结束（无flag）→ 自动显示对话演出
    ↓
对话结束 → setIntroPlayed(true) → 保存存档 → 进入游戏
```

**下次进入存档时的判断**：
```
读取存档 → 检查 INTRO_PLAYED flag
    ↓
    ├─ true  → 直接进入游戏场景
    └─ false → 重新播放视频 → 对话 → 设置flag → 进入游戏
```

**设计优点**：
- 简化 flag 管理，不需要追踪视频和对话两个独立状态
- 保证玩家必须完整看完开场才能进入正式游戏
- 中途退出也不会丢失进度（flag 未设置，会从视频重新开始）

**修复**（改用 Map 存储多场景）：

```typescript
private _preloadedSceneMap: Map<string, Node> = new Map();

public preloadNextScenes(): void {
    const config = DataManager.instance.getSceneConfig(this._currentSceneId);
    const preloadList = config?.preloadNext || [];

    // 先清空旧的预加载（切换场景后相邻场景变了）
    this._preloadedSceneMap.clear();

    preloadList.forEach((sceneId: string) => {
        this.preloadSceneForSwitch(sceneId);
    });
}

public preloadSceneForSwitch(sceneId: string): void {
    if (this._preloadedSceneMap.has(sceneId)) return;

    ResourceManager.instance.loadScene(sceneId).then((prefab) => {
        const node = instantiate(prefab);
        node.name = sceneId;
        this._preloadedSceneMap.set(sceneId, node);
    });
}

public switchToScene(sceneId: string, transitionType: string = "fade"): void {
    // ...
    if (!this._preloadedSceneMap.has(sceneId)) {
        // 未预加载，同步加载
        ResourceManager.instance.loadScene(sceneId).then((prefab) => {
            this._doSwitch(sceneId, instantiate(prefab));
        });
    } else {
        // 已预加载，从缓存取
        const node = this._preloadedSceneMap.get(sceneId);
        this._doSwitch(sceneId, node);
    }
}
```

### 问题详解

#### 问题1：物品消耗后选中状态

**场景**：玩家选中"钥匙"使用后，钥匙被消耗（`ITEM_REMOVED`），但 `_selectedItem` 仍指向这把钥匙。

**需求**：`_selectedItem` 指向的物品被移除时，自动取消选中。

**修复**：InventoryManager 监听 `ITEM_REMOVED`，同步取消选中状态。

```typescript
onLoad() {
    director.on("ITEM_REMOVED", this._onItemRemoved, this);
}

private _onItemRemoved(itemId: string): void {
    if (this._selectedItem === itemId) {
        this._selectedItem = null;
        director.emit("ITEM_DESELECTED");
    }
}
```
